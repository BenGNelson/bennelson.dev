the homelab

Everything on the dashboard runs on hardware in my basement. This page is the tour — what it is, how it's wired, and what it has taught me the hard way.

the basement

Self-hosting is the whole personality of this setup: if I use it every day, I want it running on something I can physically reach. The result is a fleet of machines with one production server at the center — a mid-tower in the basement that runs the media server, the network storage, home automation, and every app on the dashboard, all day, every day.

A note on names: every machine below is renamed for publication. The real hostnames stay home; the kitchen appliances are stand-ins. The real names are better. You'll never know. the real names are frogs. wait. forget i said that.

the media pipeline

The flagship automation: a friend asks for a movie on the request portal, and a pipeline picks it up — request service → indexer manager → download automation → quality profiles → subtitle sync → it appears in the library, usually before they've made popcorn. Every piece runs in its own pinned container as a non-root user, none of them can touch the Docker socket, and the one thing facing the internet sits behind an auth wall at the edge before a single packet reaches the house.

The philosophy everywhere: deny by default, pin versions, automate the boring, write down the weird. The "write down the weird" file is longer than some novels.

mission control

All of it is observable from home-hq, the self-hosted dashboard that started this whole thing — server vitals, container states, media stats, solar, weather, backups, network. The real one never leaves the house, but there's a full simulation with canned data you can click around.

war stories

Uptime is a lagging indicator of lessons learned.

The enclosure that cried drive-failure

An external drive started throwing I/O errors that looked exactly like a dying SSD. The drive was fine — the USB bridge chip in its enclosure was hanging under sustained load. It now has a watchdog that detects the wedge and power-cycles the bridge before anyone notices.

moral: blame the cheapest chip in the chain first.

The setting that read correctly and did nothing

One torrent-client toggle, quietly off, meant every download silently ignored its category's save path — so every import fell back from an instant hardlink to a full copy, eating double disk. Every UI showed the category as correct while it did precisely nothing.

moral: verify behavior, not settings screens.

The updater that needed updating

The container that auto-updates my other containers crash-looped after a Docker upgrade, because the project had been archived and its API client aged out. Replaced with a maintained fork; the irony was noted in the commit message.

moral: your maintenance tools need maintenance too.

The backup that looked automatic

A disaster-recovery document sat inside a backed-up folder, which made it feel self-updating. It was a manual copy. It had been stale for seven weeks before anyone checked. The procedure now ends with "copy it across, by hand, now."

moral: a backup you haven't verified is a rumor.

rules of the lab

1. Nothing at home listens to the open internet; the edge does the listening.
2. Every public name on this page is a pseudonym — numbers are fine, names are not.
3. If it isn't backed up off-site, it doesn't exist.
4. The alarm system is out of scope for automation. Permanently. On purpose.
5. Boring technology, pinned versions, written runbooks.
